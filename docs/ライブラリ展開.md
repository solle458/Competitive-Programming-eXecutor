# ライブラリ展開

`cpx merge` がコンテスト解答とライブラリヘッダから提出を作る規則。用語は [CONTEXT.md](../CONTEXT.md)。

## コンテスト解答

- 挿入位置は `/* -- libraries --*/`
- ディスク上の解答ファイルは書き換えない
- 解答に書いてある `using namespace` は提出に残す

## 公開ヘッダ

- 本体区切り `/* -- library code --*/` は書かない。公開する前に消す
- `#pragma once` と `using namespace` で始まる行は、ヘッダに残してよい。提出には出さない
- `using Name = ...` と `using Base::name` はライブラリ本体であり、提出に残す
- `#include` はライブラリ本体に残さない

## 提出

1. 解答と、辿ったヘッダから `#include` を集める。同じものは1回
2. `.hpp` でない include は、提出の先頭へ `#include <...>` として書く
3. `.hpp` は `library_dirs` から読み、依存を先、取り込み元を後にして展開する
4. ヘッダから落とす行は、`#pragma once`、`#include`、空白を除いて `using namespace` で始まる行、本体区切りそのものの行
5. 残った行をライブラリ本体として、挿入位置の直後に書く
6. 本体の途中にある `#include` も、先頭へまとめる

## テンプレ

新規ヘッダのテンプレに本体区切りを書かない。

## 今回やらないこと

- `namespace solle` は入れない。クラスはグローバルのまま。修正候補は [issue 16](https://github.com/solle458/Competitive-Programming-eXecutor/issues/16)

## 失敗

- 展開するヘッダがあるのに挿入位置が無いときは、提出を書かず失敗する
- ヘッダが `library_dirs` に無いときは失敗する
